# MurchCalc План разработки браузерного калькулятора

## 1. Концепция и требования

### 1.1. Основные режимы

- **Basic Mode** — классический калькулятор с кнопками (для мобильных/простых задач).
- **Text Mode (главная фича)** — построчный ввод выражений с мгновенным вычислением ответа справа, поддержка комментариев и переменных.
- **Spreadsheet Mode** — упрощённый Excel-подобный режим с ячейками и формулами.
- Возможность легкого добавления режимов вроде конвертера валют и тп.

### 1.2. Ключевые ограничения

- Работа полностью на клиенте (без сервера) — хостинг на GitHub Pages.
- Расширяемая архитектура (легко добавлять новые режимы и функции).
- Persistent state — сохранение работы в LocalStorage/IndexedDB.

```
│   │   ├── parser.ts      # AST
│   │   ├── evaluator.ts   # Вычисление AST
│   │   ├── functions/     # Реестр функций (sin, sqrt...)
│   │   └── units.ts       # Единицы измерения (опц.)
│   ├── context/           # Переменные, состояние вычислений
│   └── types.ts

│   ├── ModeRegistry.ts
│   ├── text/
│   ├── spreadsheet/
│   └── basic/
├── ui/                    # Компоненты интерфейса
│   ├── components/
│   ├── layout/
│   └── theme/
├── storage/               # Персистентность
├── utils/
└── main.ts
```

### 3.1. Интерфейс режима (для расширяемости)

```ts
interface CalculatorMode {
  id: string;
  title: string;
  icon: string;
  mount(container: HTMLElement, engine: Engine): void;
  unmount(): void;
  serialize(): unknown; // для сохранения
  deserialize(data: unknown): void;
}
```

Новые режимы регистрируются в `ModeRegistry` — добавление режима не требует изменения ядра.

### 3.2. Разделение ядра и UI

Движок (`core/engine`) не знает про DOM. Это позволяет:

- переиспользовать его во всех режимах;
- тестировать изолированно;
- потенциально запускать в Web Worker (для тяжёлых вычислений).

## 3. Математический движок (сердце проекта)

### 4.1. Этапы обработки выражения

1. **Lexer** — строка → массив токенов (числа, операторы, идентификаторы, скобки).
2. **Parser** — токены → AST (алгоритм Shunting Yard или Pratt parsing).
3. **Evaluator** — обход AST → результат с учётом контекста переменных.

### 4.2. Что поддерживать

- Арифметика: `+ - * / % ^`
- Скобки, приоритеты операторов
- Функции: `sin, cos, sqrt, log, abs, round, min, max...`
- Константы: `pi, e`
- Переменные: `x = 5`
- (Позже) единицы измерения, проценты в контексте (`100 + 10%`)

### 4.3. Реестр функций (расширяемость)

```ts
FunctionRegistry.register("sqrt", {
  arity: 1,
  fn: (x) => Math.sqrt(x),
});
```

### 4.4. Точность

Использовать `decimal.js`, чтобы избежать `0.1 + 0.2 = 0.30000000000000004`.

## 4. Text Mode / Режим заметок (главная фича)

### 5.1. Функциональность

- Многострочный редактор: слева выражение, справа результат.
- Мгновенный пересчёт при вводе (debounce ~150ms).
- Переменные, объявленные на строке, доступны на следующих строках.
- Комментарии (`// текст`).
- Ссылки на предыдущий результат: `prev`, `$3` (строка 3), `sum` (сумма всех строк выше).
- Обработка ошибок: подсветка проблемной строки без падения остальных.

### 5.2. Модель данных

```ts
interface Line {
  id: string;
  raw: string; // текст строки
  type: "expr" | "comment" | "assignment" | "empty";
  result?: number | string;
  error?: string;
}
```

### 5.3. Реализация редактора

- **MVP:** `<textarea>` + отдельная колонка результатов.
- **Продвинуто:** CodeMirror 6 — подсветка синтаксиса, автодополнение переменных/функций, inline-виджеты результатов.

### 5.4. Пересчёт с зависимостями

При изменении строки пересчитывать её и все зависящие от неё строки (граф зависимостей переменных).

## 5. Spreadsheet Mode / Режим таблици (упрощённый Excel)

### 6.1. Функциональность

- Сетка ячеек (A1, B2...).
- Формулы через `=` (`=A1+B2`, `=SUM(A1:A5)`).
- Ссылки на ячейки и диапазоны.
- Пересчёт по графу зависимостей.
- Обнаружение циклических ссылок.

### 6.2. Модель данных

```ts
interface Cell {
  raw: string;
  computed: number | string | null;
  formula: boolean;
  dependencies: string[];
  error?: string;
}
type Sheet = Map<string, Cell>; // ключ "A1"
```

### 6.3. Переиспользование движка

Формулы ячеек используют тот же evaluator, что и Text Mode — добавляется лишь разрешение ссылок на ячейки.

### 6.4. Реализация сетки

- **MVP:** HTML-таблица с редактируемыми ячейками.
- **Продвинуто:** виртуализация строк для больших таблиц.

## 7. Хранение данных

- **Автосохранение** в LocalStorage (MVP).
- Переход на **IndexedDB** для нескольких документов/больших таблиц.
- Формат: версионируемый JSON (`{ version, mode, data }`) — для миграций в будущем.
- Экспорт в файл / импорт из файла.

## 8. Тестирование

| Уровень     | Что тестировать                   |
| ----------- | --------------------------------- |
| Unit        | Lexer, Parser, Evaluator, функции |
| Integration | Пересчёт зависимостей, режимы     |
| E2E (опц.)  | Playwright — сценарии ввода       |

Особое внимание — краевые случаи: деление на ноль, циклы ссылок, некорректный ввод.

## 9. Деплой на GitHub Pages

1. `vite.config.ts` → задать `base: '/repo-name/'`.
2. GitHub Actions workflow:
   - trigger на push в `main`;
   - `npm ci && npm run build`;
   - публикация папки `dist` в GitHub Pages.
3. Включить Pages в настройках репозитория (source: GitHub Actions).

Пример workflow-шага:

```yaml
- run: npm ci && npm run build
- uses: actions/upload-pages-artifact@v3
  with: { path: dist }
```
